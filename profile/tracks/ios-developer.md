# Track: iOS Developer

Use for iOS Engineer, Mobile Engineer, Swift Developer, and any role where shipping to the App Store is the job.

## Positioning

A senior-leaning iOS engineer who builds reusable frameworks rather than one-off screens, and who brings genuine machine learning depth that most iOS candidates do not have. That combination is rare and it is worth money in on-device ML, Core ML, and camera or sensor heavy products.

## Summary template

> iOS Engineer with four years shipping production applications in Swift and SwiftUI, with a track record of building reusable components and frameworks used across projects. M.Sc. in Artificial Intelligence, with applied experience in computer vision and on-device inference. Comfortable owning a feature from architecture through App Store release.

## Lead projects, in order

1. **StoryTeller**, the iOS client for the Bedtime Story Teller backend. SwiftUI with MVVM, a typed API layer, and streamed LLM responses over WebSockets. This is a full product, not a component, and the streaming work is real engineering. It also carries the AI differentiator without you having to argue for it.
2. **The SwiftUI package set.** Five published, reusable, documented components. The senior signal. API design, backwards compatibility, writing for other developers.
3. **Dolidroid**, framework design for enterprise use.
4. **TodoPharma**, commercial delivery, if you can disclose it.

Before using StoryTeller in an application, write its README. Right now the repo opens on an empty README and an Xcode project called `InteractiveAvatarDemo`, which actively works against you.

## Skills order

Swift, SwiftUI, UIKit, Swift Package Manager, Fastlane, XCTest, CI/CD, Git, clean architecture and design patterns

Then a single ML line: Python, PyTorch, Core ML, OpenCV.

## What to emphasise

- Four years of production, App Store shipped work
- Framework and package authoring, not just feature work
- Release engineering, Fastlane and CI/CD
- ML depth as a differentiator, one or two sentences, not a section

## Where this track is strongest

Postings mentioning Core ML, on-device inference, camera pipelines, AR, or health and sensor data. There your dual profile stops being "unfocused" and becomes the exact hire. Score those higher and tailor them harder.

## Watch for

Interviewers reading the dual profile as indecision. Pre-empt it in the letter with one line: the ML is what you build with, iOS is where you ship it. Own the combination rather than apologising for it.
